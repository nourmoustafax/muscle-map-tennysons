# MuscleMap reproducible release

## Product scope and approach

Extend the existing Vite/TypeScript app into a complete local-first, reproducible musculoskeletal evidence-to-review workflow. Do not claim operational approval, autonomous diagnosis, exercise prescription, live spacecraft integration, or continuous CSA sensing. The supplied complete development instructions govern this release; earlier MVP claims must be revisited rather than carried forward unchecked.

First obtain actual source files where possible, preserve originals and compute hashes. The previous reference fixture is not NASA data and must leave the research workspace. Research, simulated mission, and manually entered observations occupy separate namespaces and cannot share a baseline or silently join. If real files are unavailable, the research view must be empty with access instructions, and the simulation must remain explicitly fictional.

The pure engine selects a participant, source mode, anatomical region, modality, and true study day. Baselines require explicit source reference identity; missing and non-comparable rows remain visible. Anatomy-function alignment separately checks participant, namespace, provenance, laterality, anatomical relevance, method and time window. The UI tells one coherent story: what was observed, what is or is not comparable, and what review is justified. A new exercise event never updates CSA.

Use actual licensed anatomical meshes for Three.js rotation, zoom, selection and highlighting. Preserve exact right quadriceps group versus right medial gastrocnemius mapping. Other visible muscles are orientation context without invented health status. A WebGL failure exposes an accessible measured-region selection fallback, not a false model-success claim.

CSV/JSON files pass a normalized preview and atomic validation before local persistence. Canonical adapters accept only documented units, timestamps/phase labels, identity and provenance. Duplicate/out-of-order records are handled explicitly. The app catches storage errors and keeps user data exportable. Local persistence is not encryption or clinical access control.

Follow-up is a structured local draft with action, note, participant, region, mode and evidence references; export captures source rows, inputs, exclusions, policy limits and timestamps. A secondary emergency-support overlay accepts incident text, shows non-diagnostic conservative safety notices and public reference limitations, and documents the incident. No public article is represented as an approved flight procedure, and no generative treatment is provided.

## Architecture and serving

The app remains static; no backend or secret is needed. Vite serves development on 0.0.0.0:3000. The hosted build installs the pinned lockfile then builds dist. The archive includes dist plus a standard-library Python local server for offline use without Node installation; source development uses the documented pnpm commands. A local service worker supports offline reload after initial caching, with external references explicitly online-only.

src/domain.ts owns canonical types and anatomy mapping. src/engine.ts owns deterministic analysis. src/ingestion.ts owns import parsing and validation. src/store.ts owns versioned local storage error handling. src/anatomy.ts owns the Three.js viewer and resource disposal. src/emergency.ts owns the conservative incident rule/reference presentation. src/main.ts owns UI integration. data/raw holds original downloaded research files; public/data holds prepared source records. assets and public/assets carry anatomy attribution/source and web assets. scripts hold acquisition, transformation, verification and archive tooling. tests hold unit, integration and browser journeys; docs hold source studies, mission integration, licensing, challenge and final verification.

## Design

Preserve Mission Control Editorial but refine readability and functionality: near-black instrument surface, mint for selected anatomy, muted amber for evidence limits, readable system sans and monospace time/provenance labels. A narrow sidebar separates monitoring, observation register, source library, mission context and secondary emergency support. The monitoring surface pairs a full-body anatomical explorer with region-specific narrative, evidence timeline, source detail and a direct follow-up path. Status is always named in text, not only color. Motion is subtle, respects reduced-motion, and stops when the model is idle. All core functions have keyboard paths and responsive layouts.

## Delivery

Run unit/data/integration/browser tests and document only executed results. Include source, local meshes and licenses, permitted datasets, retrieval/preparation scripts, lockfile, tests, README and verification report in a ZIP. Verify ZIP integrity and exclusion of secrets and machine-specific dependencies. Save a canonical checkpoint; do not republish unless explicitly requested in this current development request.
